# 墨织项目开发范式（私有提炼版）

> 提炼自 2026-06-15 → 2026-10-15 四个月、240+ 提交、V5.3 → V10.1 的完整开发史。
> 本文档存放于 `.workbuddy-ai/`（已忽略目录），永远不会进入公开快照。
> 用途：① 自我备忘 ② 未来若想分享"如何用 AI 做项目"，此为底稿。

---

## 一、总纲：一句话范式

**把大项目切成一个个"班次"，每个班次改动面收敛、门禁全绿、真机验收、留痕复盘——让 AI 干活，但让证据说话。**

---

## 二、班次工作流（核心节拍）

1. **盘点先行**：动手前先做全量盘点（代码规模/目录/历史/文档），不凭印象
2. **方向文档**：盘点 → `outputs/下一步方向_xxx.md`（三步走 + 明确不建议项），决策点列清
3. **一个班次 = 一个可交付主题**：功能班 / 治理班 / 验收班 / 发布班，不混车
4. **决策点拍板制**：涉及产品边界/功能删减/对外发布，列选项 + 推荐 + 理由，用户拍板后执行；其余全速推进
5. **收尾三件套**：CHANGELOG 班次叙事 + 版本号同步（四处）+ 提交信息带验收数据

## 三、门禁文化（质量棘轮）

- **五道门禁**：tsc → vitest → vite build → 边界审计 → cargo test，全绿才出船
- **棘轮基线**：死命令/幽灵调用/死配置/TS 孤岛只许降不许升；清理后下调水位
- **登记 + 复核期限**：刻意保留的债必须登记 + 带复核期限，到期未处理 → 门禁失败
- **门禁防假绿**：warm 缓存掩盖冷编译、测试按总数下限会被无关测试撑高——按功能模块设下限
- **防串台**：测试隔离（种子幂等）、reporter 选型（Windows 沙箱 teardown 卡死对策）

## 四、真机验收方法论

- **代码层全绿 ≠ 运行正确**——V8.7 连写覆盖 P0 事故的教训：门禁四绿但用户流程断裂
- WebView2 + CDP（9223）直连真机，Playwright 断言 + 截图留档 + VLM 打分
- **modal 内定位必须限定 modal 容器**（背景层同名按钮被遮罩拦截 → 伪失败）
- **Playwright 种子必须幂等**（addInitScript 每次 reload 重执行，否则打回种子值伪装"丢稿"）
- 全屏层开关走事件派发，不走键盘时序（flaky 源）

## 五、诚实复盘文化

- 复盘区分「真错」与「顺序问题」，不夸大不自责
- 错误归因到**方法论**而非情绪（例："搜调用应搜符号名，不搜路径模式"）
- **CI 绿只证明测试通过，不证明功能正确**——必要条件不当充分条件用
- 记忆会过时：关键结论周期性实测复核，防"记忆驱动的误判"

## 六、巨石治理（架构演进法）

- 千行文件按**域**逐刀出舱：JSX 逐字搬迁、行为零变化、每刀独立可回滚
- 已证明的模式：组件出舱（纯展示）/ hook 出舱（逻辑域）/ barrel 兼容（消费方 import 零变化）
- 顺序：先低风险展示组件 → 逻辑域 → 核心管线（单独立班 + 全量回归）
- 每刀验收：四门禁 + E2E + （需要时）真机回归

## 七、发布仪式（公开线/私有线分离）

- 本地 master = 私有线（记忆/内部文档/完整历史）
- 公开 = **孤儿提交快照**（不带历史），前置：密钥扫描 + 内部文件移出 + 范式文档抽离
- lock 由 Linux runner 权威生成（Lockfile 工作流自提交）；Release 打 tag 自动构建
- 发布后：验证下载链 + CI 绿 + 草稿转正式

## 八、AI 协作纪要

- AI 是"高耐心高记忆的执行者 + 诊断者"，**决策权始终在用户**（拍板制）
- AI 的常见失误（已内化为准绳）：凭印象下结论（必须实测）、把必要条件当充分条件、报喜不报忧（未做的如实记录）
- 好用的 AI 任务形态：盘点、诊断、机械搬迁、文案起草、探针脚本；慎用形态：无验收的核心重写

## 九、债务观

- 债务登记可见 + 带期限，比"假装没有"健康
- "明确不做项"与"要做项"同权重记录（附理由），防战略漂移
- 净复杂度是真实指标：加新的同时必须清旧的
