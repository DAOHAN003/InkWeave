# 万象写作方法论 v3

> 不是人写小说，是世界长出小说。  
> 方法论在我脑子里，分身只拿 15 行指令。  
> **引擎是写作的前置条件，不是可选项。**

---

## 一句话流程

```
引擎跑通（数据源适配 + 状态检查）
  → 大纲走引擎（万象数据 + 伏笔 + 角色锁）
  → writer_dispatch.py 生成 prompt
  → 分身写 5 章（每章 3000 字）
  → auto_pipeline.py 修格式
  → 质检（故事性 + 格式）
  → FAIL 的章重写
  → 每 30 章回收精华 + 进化标准
  → 更新状态文件
  → 下 5 章
```

---

## ⚡ 引擎优先（v3 铁律）

**引擎不是辅助工具，是写作的呼吸系统。没有引擎的写作是裸写，裸写 = 废稿。**

### 开写前三问（每次必问）

1. **引擎跑通了吗？** → `python writer_dispatch.py --status` 无报错
2. **数据源接上了吗？** → `novel_config.json` 里的数据路径可读
3. **状态文件是最新的吗？** → `story_state.json` 的 `last_chapter` 和实际章节一致

**三问任一答 No → 先修，不写。**

### 引擎优先原则

- 写任何章节前必须先确认引擎跑通
- 分身的 prompt **必须** 由 `writer_dispatch.py` 生成，**禁止手写 prompt**
- 如果引擎跑不通，**先修引擎**，不能绕过引擎裸写
- 裸写 = 废稿（除非紧急情况且老大明确批准）
- 引擎白做了等于没用 → 每次写作必须走引擎流程

## 28 条写作方法（精选 12）

### 基础写法

1. **情绪用身体写** — 不写"他很愤怒"，写"他的牙关咬得咯咯响"
2. **对话前后写动作** — 不写"他说"，写"他放下茶杯，说"
3. **用动作开场不用天气** — 不写"今天天气晴朗"，写"他推开门"

### 场景构建

4. **物品法则** — 每个场景至少 3 个具体物品
5. **八维度场景描写** — 视觉 / 听觉 / 嗅觉 / 触觉 / 味觉 / 温度 / 光线 / 空间感
6. **空间感建立** — 先写大环境，再写小细节

### 情感与死亡

7. **死亡写法** — 用最后一个动作写死亡，不写"他死了"
8. **金句写法** — 金句不超过 15 字，放在段落结尾
9. **传承写法** — 传承用物件承载，不写"他继承了遗志"

### 冲突与转折

10. **冲突模板** — 冲突 = 目标 + 阻碍 + 行动，不写"他们打起来了"
11. **微量变化** — 日常章用微小变化推进，不写"日子一天天过去"
12. **反高潮** — 高潮后接平静，不连续高潮

## 15 条铁律（v3 版）

### 原有铁律（v2）

1. 5 章一个分身
2. prompt 不超 20 行
3. 不让分身读文件 —— 信息贴在 prompt 里
4. 写完跑 `auto_pipeline.py`
5. 质检不过才重写（大部分脚本能修）
6. 角色信息从 `character_lock.json` 来
7. 大纲从万象数据来不要人编
8. 每 30 章提取精华 + 进化标准
9. 每批开写前更新 `story_state.json`
10. 不赶进度不跳步骤

### v3 新增铁律

11. **引擎跑不通不开写** — 引擎是前置条件，不是可选项
12. **分身不裸写** — prompt 必须由 `writer_dispatch.py` 生成，禁止手写
13. **大纲也走引擎** — 大纲基于万象数据 + 伏笔 + 角色锁生成
14. **状态文件实时更新** — 每批完成后立刻更新 `story_state.json`
15. **伏笔每批必检** — 开写前检查 `foreshadow.json`，到期伏笔必须安排回收

## 18 条血泪教训（精选 8）

### v3 新增教训（2026-05-08）

1. **引擎白做了等于没用** → 引擎是写作的前置条件，不是可选项
2. **分身裸写质量不可控** → 即使大纲足够详细，分身直接拿大纲裸写也会丢失伏笔追踪、角色锁定、精华匹配
3. **数据源不通用引擎就跑不通** → 跑不通 → 自然不会用 → 引擎白做
4. **大纲手写脱离世界数据** → 大纲不走引擎，就不会检查伏笔回收时机，不会参考角色最新状态
5. **多分身无协议等于各干各的** → 必须有调度协议：谁先谁后、谁生成 prompt、谁做审查
6. **分身不读文件！信息贴在 task 里！** → 让分身自己去读文件 = 浪费时间 = 超时
7. **不给信息 ≠ 精简，分身是执笔者不是创作者** → 正确做法：我消化后给精华
8. **动作级大纲越详细，正文质量越高** → 每章动作级大纲必须 300-500 字，含具体动作、对话、感官细节、小动作收尾

## 完整写作流程（v3 版）

```
┌──────────────────────────────────────────┐
│ 0. 新小说接入：适配数据源                   │
│    → novel_config.json 配置 data_source    │
│    → writer_dispatch.py --status 验证      │
├──────────────────────────────────────────┤
│ 1. 引擎检查：三问确认                       │
├──────────────────────────────────────────┤
│ 2. 大纲生成（走引擎）                       │
│    → 万象数据 + 伏笔检查 + 角色锁           │
│    → 每批最多 20 章                         │
├──────────────────────────────────────────┤
│ 3. prompt 生成（引擎生成，禁止手写）          │
├──────────────────────────────────────────┤
│ 4. 分身写作（5 章 / 批）                    │
├──────────────────────────────────────────┤
│ 5. 后处理 → auto_pipeline.py 修格式        │
│    → 更新 story_state.json                 │
├──────────────────────────────────────────┤
│ 6. 质检（主体执行）                         │
│    → 故事性检查 > 格式检查                   │
├──────────────────────────────────────────┤
│ 7. 精华回收（每 30 章）                     │
└──────────────────────────────────────────┘
```

---

## 质检标准（侧重故事，不是格式）

1. **有事发生**：章末和章初处境不同
2. **人物有行动**：不是只观察，做了选择
3. **对话区分**：遮住名字能分辨谁说的
4. **无复读**：没有大段重复
5. **连续性**：和上一章衔接
6. 字数 2500-3500
7. 禁用词为零

格式问题（比喻 / 叠词 / 短行）全交给 `auto_pipeline.py` 修。

---

## 速度

- 5 章一批，每批 15-25 分钟（分身写）+ 1 分钟（auto_pipeline）
- 一天跑 8 轮 = 40 章
- 并行 4 个分身 = 160 章 / 天
- 1200 章 = 8-10 天
