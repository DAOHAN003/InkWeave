## 三、三个真正的风险 / 缺口

**R1 · 工作树无检查点（最高优先级，丢不起）**
P1/P3/P4/P5 约 43 文件 +1701 行未提交；且**缺 `.gitattributes`** 导致 git 报 LF↔CRLF 噪音（疑似 `core.autocrlf`）。一旦误操（reset / checkout / 磁盘问题）即丢失数月成果。→ 先提交。

**R2 · 题材 / 通用参数未接动力学（决定产品承诺）**
`--scan` 实测：`world_type` 与 `energy_density` / `order_level` / `chaos_level` / `life_fertility` / `resource_abundance` 当前为**"标签性"**——同 seed 换题材世界逐字节相同，仅规则元数据不同。只有 `max_entities` / `death_protection_init` 真正影响（在 `spawn.rs` 被读）。
→ 要让"不同模板→不同世界"落地，必须接 **GenreKit**（把这些字段接进 spawn / 事件 / 选择逻辑）。`--scan` 本身就是它的回归 / 验收工具。

**R3 · 文档失真（误导新人）**
`ARCHITECTURE.md` / `MODULE_MAP.md` / `万象完整功能清单.md` 是已退役的 Python 1.0（673 Python + 54 C++ 头文件那套）；`万象2.0技术讲解.md` 偏旧（仍写 127 测试、缺 P1/P3/P4/P5）。
→ 归档或顶部标注"已废弃/参见 STATUS.md"，并刷新 2.0 讲解文档。

**次要**：G2 配置去硬编码未全收口（仅 `wanxiang_world` 完成）；G3 认知增强默认关；散文仍有少量导火索描述重复与个别原始名泄漏（如 `新灵_0`，可读性打磨项，非阻塞）。

## 四、顺着思路能走到的最优（路线图）

**定位锚（用户已定，不可动摇）**：万象 = **确定性世界模拟 / 可实验引擎**（世界本身：运行态、可观测、可对比、可分支、守守恒律），**不是写小说工具**。散文 / 看板只是世界的可读导出视图。
**护城河**：确定性可复现 + 可对比(diff/fork) + 守恒可信 + agent 涌现。一旦做成"问一句答一段"即丢护城河。

按性价比排序：

- **T0 · 收口保护（零功能风险，立即做）**
  加 `.gitattributes`（`* text=auto eol=lf`）+ 把 P1..P5 按主题拆 4-5 个 commit 提交。消除最大风险。

- **T1 · 题材真正塑形世界（GenreKit）← 当前最关键的能力跃迁**
  把 `world_type` + 通用标量接进 spawn / 事件 / 选择逻辑；用 `--scan` 做回归 / 验收（目标：让 `energy_density` / `order` / `chaos` / `life_fertility` 等从"不影响"变成"影响"且彼此可区分）。
  这是"不同模板→不同世界"承诺的**唯一兑现路径**，也是区别于一切 LLM 写作 / 聊天产品的关键。

- **T2 · SDK 硬化 + World Lab 互动化**
  `wanxiang_sdk::WorldModel` 已就位；补 `fork` / `branch` / `compare`（基于 checkpoint + diff），出稳定文档；World Lab 实验区从"静态矩阵"升级为"规则滑块 → 重跑变体 → 并排 diff"的交互。这是护城河最直观的对外演示。

- **T3 · 规模化与深度**
  10k+ 实体 / 长程性能；O(1) 存档（rng 状态直存，与现有 checkpoint 接口兼容）；配置去硬编码收口（Task A）；在确定性 / 测试契约稳固后评估认知增强默认开启。

- **T4 · 下游证明**
  做一个最小下游消费者（游戏后端 / 小说-as-消费者 demo）拉 `WorldModel` 数据，实证"引擎非小说"的架构判断。
