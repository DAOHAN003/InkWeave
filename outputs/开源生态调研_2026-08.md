# 开源生态调研：什么适合与 FuxiLoom 一起用

> 调研时间：2026-08-29 · 针对 FuxiLoom（Tauri v1 + React/TS + Rust 本地小说引擎）的实际集成价值排序
> 结论分层：**A 能直接接（零/低代码）→ B 值得抄思路 → C 不建议现在碰**
> ⚠️ 部分信源为聚合站/营销号，star 数与活跃度请自行到 GitHub 核实后再决策。

---

## A. 能直接接（今天就能用）

### A1. 嵌入模型本地化 —— 最高性价比，零代码改动 ⭐ 首推

**做什么**：把语义 RAG 从云端 bge-m3 换成本地 Ollama 的 bge-m3，前情召回质量升一档且完全离线。

**为什么现在值得做**：FuxiLoom 的嵌入配置留空时会回退「内置离线词向量」（字面共现），语义召回能力弱。接本地 bge-m3 后可识别近义/改写前情，直接提升长篇连贯性。

**依据（代码实锤）**：
- `src/utils/ai/request.ts:73` — baseUrl 含 `localhost`/`127.0.0.1` 时不校验 API Key
- `ModelSettingsPanel.tsx:634` 原文提示：支持「本地 Ollama 的 OpenAI 兼容接口（如 http://localhost:11434/v1）」

**操作**（真机，PowerShell 或 CMD 均可，只复制命令本身）：
```
ollama pull bge-m3
ollama list
```
然后在 FuxiLoom → 模型设置 → 语义嵌入区填：
- 嵌入 Base URL：`http://localhost:11434/v1`
- 嵌入模型名：`bge-m3`
- 嵌入 API Key：**留空**

**模型规格**：BAAI/bge-m3，Apache 2.0，1024 维，约 1.2–2.1GB，100+ 语言，稠密+稀疏+多向量混合检索。中文 RAG 开源标杆。

---

### A2. 写作主力模型选型 —— 你双卡 28GB 的档位

| 模型 | Q4 显存 | 你的适配 | 说明 |
|------|---------|----------|------|
| `qwen3:14b` | ~9.5GB | ✅ 3060 12GB 单卡即可 | 稳妥起步，长文写作够用 |
| `qwen3:32b` | ~20.5GB | ✅ 5060Ti 16GB 单卡勉强 / 双卡轻松 | 质量明显跃升 |
| `qwen3.6:35b-a3b` | ~22-24GB | ✅ 双卡 | 项目预设默认值，MoE 速度近小模型 |

**建议路径**：先用 `qwen3:14b` 把整条写作链路跑通（快、稳、不折腾），确认流程无误后再上 32B/35B 提质量。**不要一上来就上最大的**——先证明流程通，再优化质量。

---

### A3. `qwen3-8b-novel-base-sft` —— 专为中文网文微调，但⚠️有坑

- Apache 2.0，基于 Qwen3-8B 全参数微调，语料 = **669 本中文网文 / 约 7200 万字**（言情、耽美、都市、奇幻、网游），专门学中文网文叙事风格与角色对话模式。
- 8B 尺寸，你机器上秒开，显存压力极小。
- ⚠️ **关键限制（模型卡自述）**：`Lacks safety alignment, not a general-purpose instruction model` —— 它是 **Stage1 base 模型**，设计用途是给下游 LoRA 当基座，**不是开箱即用的对话/指令模型**。直接用很可能「不听指令、续写风格对但难以控制」。
- 配套 LoRA（同作者）：叙事单元分类 / 场景边界检测 / 角色归属辅助。
- **判断**：值得关注、值得实测，但**不要指望它直接替代你的写作主力模型**。若要用，建议等社区出 instruct 版，或做好自己挂 LoRA 的准备。

## B. 值得抄思路（不直接集成）

### B1. Openwrite —— 长篇上下文管理，最值得抄 ⭐
- 开源 AI 小说创作 Agent 框架，**四层大纲压缩**，稳定服务 **400 万字**篇幅。
- 双 Agent 分工（宏观大纲 / 微观正文解耦）+ **DAG 有向无环图 + Embedding** 管理角色关系、伏笔、正文关系。
- 还有：静态与动态文件防遗忘机制、全局 Skill 导入、拆书分析、剧情多线推演。
- **对 FuxiLoom 的价值**：FuxiLoom 已有「百万字长篇管理」与 RAG 前情，但**四层大纲压缩 + DAG 伏笔管理**是明确的增强方向，思路可直接借鉴。

### B2. Vela —— 同赛道最直接竞品，必须研究 ⭐
- 2026 年 4 月开源，**本地优先、隐私安全**的 AI 长文/小说创作 IDE。
- 技术栈 **Electron + React + TailwindCSS + Zustand** —— 与 FuxiLoom（Tauri + React + TS）几乎同构。
- 特性：BYOK（支持 Ollama 直连）、**内置 RAG 向量知识库**（一键导入设定集，生成时自动提取上下文减幻觉）、世界观→大纲→章节→精修工作流、类 VSCode 多侧边栏。
- **对 FuxiLoom 的价值**：这是定位重合度最高的项目。研究它的**设定集 RAG 导入 UX** 与**章节精修流程**，直接补 FuxiLoom 短板。

### B3. Sumeru —— 创作流程编排，可对表
- 把创作拆成 7 个可编排模块：`worldbuilder / topic / outline / write / review / polish / finalize`
- 安装：`npx skills add xindoo/sumeru`，可在 Claude Code / OpenClaw / Hermes 等 Agent 中使用。
- **对 FuxiLoom 的价值**：拿这 7 个模块跟 FuxiLoom 现有流程对表，查缺补漏（例如 `topic` 选题卖点分析、`finalize` 完稿导出）。

### B4. webnovel-writer —— 长篇记忆，社区验证最多
- GitHub 同题材 star 最高（约 5.3k），专攻「AI 写到第 200 章还记得第 1 章伏笔」，基于 Claude Code 的特殊上下文管理策略。
- 若 FuxiLoom 的长篇一致性想再上一层，值得读它的上下文策略。

### B5. 其他（了解即可）
- **InkOS Studio**：AI Agent 故事创作系统，入选首批 KIMI 开源合作伙伴，支持 Studio/TUI/CLI 三种形态，v1.5 有「自然语言创建开放世界」。
- **RWKV-6-ChnNovel**：RWKV 架构中文小说模型，续写/扩写见长，但架构非主流、Ollama 支持存疑，且项目较老 → 不建议现在投入。

## C. 不建议现在碰

| 项目 | 为什么不碰 |
|------|-----------|
| **vLLM / SGLang** | 高并发生产服务引擎（PagedAttention + 连续批处理）。FuxiLoom 是**单机单用户桌面应用**，用不上，只会增加部署复杂度。真到要服务多用户那天再说。 |
| **多模态嵌入**（Qwen3-VL-Embedding 等） | 写小说是纯文本场景，图文音视频检索用不上。 |
| **LocalAI** | 除非你要一套端点同时跑文本+图像+音频。只跑文本的话 Ollama 已经够了，别加一层。 |
| **LM Studio / Jan / GPT4All** | 都是 llama.cpp 的不同前端（Ollama 也一样）。换工具**不会改变显存上限**，解决不了「模型装不下」的问题。想要 GUI 挑模型可以装一个玩，但不必迁移。 |

---

## 一句话结论

**今天就做**：`ollama pull bge-m3` → 嵌进 FuxiLoom 的嵌入配置（Key 留空）→ 语义前情召回离线化，零代码改动、立竿见影。

**本周研究**：Vela（同赛道竞品 UX）+ Openwrite（四层大纲压缩 + DAG 伏笔），抄进 FuxiLoom 的长篇管理。

**别急**：模型先用 `qwen3:14b` 跑通全链路，别一上来堆最大模型；`qwen3-8b-novel-base-sft` 值得关注但它是 base 模型，直接用大概率不听指令。
