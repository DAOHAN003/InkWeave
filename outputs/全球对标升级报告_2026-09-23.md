## 三、本班落地项（V5.9.0）

### 结构化输出：大纲骨架链路全覆盖
V5.8.0 只接了 chapterGenerate 3a/3b/3c 三处；本班把**全书骨架生成主链路**接上 chatStructured：

| 调用点 | 层级 | schema |
|--------|------|--------|
| `generateGlobalOutline` | L1 全书大纲 | `global_outline`（coreConflict/mainPlot/ending/theme/estimatedVolumes） |
| `generateArcOutline` | L3 段落大纲 | `arc_outline`（title/summary/arcConflict/arcResolution） |
| `generateSceneOutlines` | L5 场景大纲 | `scene_outlines`（数组：title/beats/characters/mood/targetWords） |
| `generateBeatSheet` | 五拍节拍表 | `beat_sheet`（数组：action/dialogue/emotion） |

设计要点：
- **零回归**：`data=null` 时走原 try/catch fallback 逻辑，行为与 V5.8.0 完全一致；端点不支持 response_format 时 request 层 4xx 剥离重试 + 会话能力记忆。
- **顺带修复一个隐性缺陷**：`generateSceneOutlines` 原逻辑「parse 成功但非数组 → 返回 []」，调用方 OutlineTreePanel 会**清空该章既有场景**（数据丢失）；现统一走单场景兜底，与「解析失败」语义一致。
- 测试：structuredOutput.test.ts 23 过（+1 四件套就位断言）；既有「schema 库形状」遍历测试自动覆盖新 schema 的 strict 兼容性（全字段 required + additionalProperties:false）。

## 四、明确不做项（附原因）

| 项 | 原因 |
|----|------|
| **Tauri v1→v2 迁移** | 官方称「自动化大部分」，但 142 个命令 + allowlist→capability 权限模型重配，社区实测「单 app 周末工程、10 app 三周」；墨织处于收敛期，不做大手术。留作下一专门班次。 |
| **React 19 + Vite 7 + React Flow 12 栈升级** | 构建链风险，收益是性能/生态，非功能；与「最后的完善」收敛目标冲突。 |
| **Plot Hole 完整版（LLM 规则）** | consistencyCheck 定位是**零 LLM 确定性引擎**；道具去向/信息传播速度类规则需要 LLM 判断，加进去会破坏「断网可用」契约。现有确定性规则（角色沉睡/伏笔悬置/代词翻转）已覆盖一大类。 |
| **角色立绘/Visualize** | 引入图像生成依赖，与「本地优先、零 Key 可用」定位冲突。 |
| **Describe 独立入口** | 五感描写建议已在 Step 3a sceneDetails 内嵌进六步管线，独立按钮是 UI 重复。 |
