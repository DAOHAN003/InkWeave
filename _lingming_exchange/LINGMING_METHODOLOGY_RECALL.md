## 二、28条写作方法（摘要）

### 基础写法（情绪/对话/开场）
1. **情绪用身体写** — 不写"他很愤怒"，写"牙关咬得咯咯响"
2. **对话前后写动作** — 不写"他说"，写"他放下茶杯，说"
3. **用动作开场不用天气** — 第一段必须有人在做某事
4. **物品法则** — 每场景至少3个具体物品
5. **八维度场景描写** — 视/听/嗅/触/味/温/光/空间（不要求全，但要有层次）
6. **结尾用小动作收住** — 不用大段总结，用一个动作/画面结束

### 死亡/战斗/突破
7. **死亡用最后一个动作写** — 不写死亡过程，写他最后做的一件事
8. **战斗写代价不写招式** — 读者不关心怎么打的，关心打赢了什么代价
9. **突破写感官** — 突破瞬间的五感变化，不写"他突破了"
10. **传承写沉默** — 传承/告别用沉默和小动作，不用台词

### 角色塑造
11. **缺席证据** — 角色不在场时留下的痕迹（桌上两杯茶但只有一人）
12. **微量变化** — 每章角色有微小变化（不是大转折，是渐进）
13. **标志性元素穿插** — 每个角色有标志性动作/物品（灰焰/霜痕/磨剑声）
14. **角色DNA锁定** — 性别/眼睛颜色/说话方式/标志物全书不变
15. **对话区分** — 遮住名字能分辨谁说的

### 节奏控制
16. **冲突模板** — 每章至少一个小冲突（不是大高潮，是张力）
17. **反高潮** — 高潮后接安静段落（不让读者累）
18. **金句写法** — 金句不超过15字，放在段落末尾
19. **克制原则** — 悲伤不哭，愤怒不吼，用克制表达强烈
20. **余韵悠长** — 章节结束留白，不把话说满

### 连续性保证
21. **前情回顾** — 每章开头有上章结尾状态（位置/情绪/未完成的事）
22. **伏笔回收** — 到期伏笔必须安排回收（foreshadow.json）
23. **状态追踪** — story_state.json实时更新（位置/同伴/活跃线索）
24. **精华回收** — 每30章提取最好段落作为"质量锚点"

### 风格控制
25. **禁用词为零** — 仿佛/宛如/犹如/竟然/然而/但是
26. **比喻≤5个/章** — 超过5个就显得花哨
27. **叠词≤2个/章** — 轻轻/缓缓/慢慢等合计
28. **短行合并** — ≤15字非对话行合并，避免碎片化

## 三、15条铁律（必须遵守的纪律）

### 批次管理
1. **5章一个分身** — 不要让一个分身写多章
2. **prompt不超20行（1500字）** — 超了分身记不住
3. **不让分身读文件** — 信息贴在prompt里

### 后处理
4. **写完跑auto_pipeline.py** — 自动削微微/禁用词/短行
5. **质检不过才重写** — 大部分脚本能修，不浪费分身时间

### 角色/大纲
6. **角色信息从character_lock.json来** — 禁止临时编
7. **大纲从万象数据来不要人编** — 引擎生成

### 精华/状态
8. **每30章提取精华+进化标准** — 越写越好的关键
9. **每批开写前更新story_state.json** — 状态最新
10. **不赶进度不跳步骤** — 宁可慢不可烂

### v3新增铁律（引擎优先）
11. **引擎跑不通不开写** — 引擎是前置条件，不是可选项
12. **分身不裸写** — prompt必须由writer_dispatch.py生成，禁止手写
13. **大纲也走引擎** — 大纲基于万象数据+伏笔+角色锁生成
14. **状态文件实时更新** — 每批完成后立刻更新story_state.json
15. **伏笔每批必检** — 开写前检查foreshadow.json，到期伏笔必须安排回收

## 四、18条血泪教训（避免踩的坑）

### 模型选择
1. **本地小模型写不了小说** → 用云端分身（或前沿本地模型如qwen3.6:35b-a3b）
2. **3段生成是给烂模型擦屁股** → 不如换好模型

### 质检
3. **格式指标≠故事质量** → 质检侧重"有没有发生事件"
4. **分身自检不可信** → 用脚本检（分身自报3000字实际可能2800或3200）
5. **赶进度跳质检=全部返工** → 宁可慢不可烂

### 引擎
6. **引擎做太多=偷懒** → 引擎只做状态追踪，写作我来
7. **引擎白做了等于没用** → 引擎是写作的前置条件，每次必须走引擎流程
8. **没有先跑引擎就开写** → 完全脱离万象引擎，引擎做了白做

### 分身管理
9. **规则太多分身记不住** → 15行prompt是极限
10. **知识库太长分身读不完** → 方法由我消化不给分身
11. **一次10章分身偷懒** → 5章一批
12. **越搞越复杂反而跑不通** → 回到最简方案
13. **分身不读文件！信息贴在task里！** → 让分身读文件=浪费时间=超时
14. **不给信息≠精简，分身是执笔者不是创作者** → 我消化后给精华+质量锚点+风格指南+每章骨架

### 大纲
15. **动作级大纲越详细，正文质量越高** → Ch126大纲最详细↗97分，Ch129大纲最粗↗68分
16. **大纲手写脱离世界数据** → 大纲不走引擎，就不会检查伏笔回收时机，和万象数据脱节

### 多分身协作
17. **多分身无协议等于各干各的** → 必须有调度协议：谁先谁后、谁生成prompt、谁做审查
18. **数据源不通用引擎就跑不通** → 新小说接入的第一步是适配数据源

## 五、动作级大纲标准（Ch126=97分的证据）

### 什么是动作级大纲

不是1-3行的摘要（如"沈夜到达残灯镇，遇到灯老"），而是**剧本级的节拍表**：

```
Ch126 动作级大纲示例（300-500字）：

【开场】沈夜蹲在残灯镇外废弃灯塔下，灰焰从指尖渗出，试探性地触碰地面裂缝。
裂缝深处传来低沉嗡鸣，像远古巨兽的呼吸。沈夜收回手，指尖残留冰冷刺痛。

【冲突】灯老从阴影中走出，扔给他一块焦黑布头。"你师父留下的。"
沈夜接过布头，袖口边缘绣着半朵残花——师父从不离身的东西。
"他死了。"灯老说得很平静，像在说天气。

【高潮】沈夜没有说话。他站起来，灰焰从脚底蔓延到全身，灯塔废墟开始震动。
灯老后退三步，眼神第一次出现波动。"你不是在哭，你是在烧。"

【收尾】沈夜把布头叠好，塞进怀里。灰焰消退，他转身离开，没有回头。
残墙上三个人的影子拉得很长——灯老、楚狂、还有沈夜自己。
```

### 动作级大纲必须包含

| 元素 | 说明 | 示例 |
|------|------|------|
| **具体动作** | 不是"他走过去"，是"他蹲下来，灰焰从指尖渗出" | ✅ |
| **具体对话** | 不是"他们聊了几句"，是"他死了。灯老说得很平静" | ✅ |
| **感官细节** | 视觉/听觉/触觉/嗅觉 | "指尖残留冰冷刺痛" |
| **收尾方式** | 用一个动作/画面结束，不用总结 | "三个人的影子拉得很长" |
| **前情回顾** | 上一章结尾状态 | 沈夜到达残灯镇外 |

### 大纲精度的质量对应

| 大纲精度 | 正文质量 | 实例 |
|---------|---------|------|
| 1-3行/章 | 60-70分，分身自由发挥=失控 | 旧版流水线Ch141-550 |
| 50字/章 | 70-80分，方向对但细节缺 | 早期尝试 |
| **300-500字/章（动作级）** | **90-97分，分身只需展开不需创作** | **精写版Ch131-140, Ch551-600** |

## 六、批量并行速度数据

### 长暮最后50章（551-600）产出节奏

```
每批规模: 10章
并行分身: 10个同时跑
每批耗时: 5-15分钟（分身写）+ 1分钟（auto_pipeline）
日产能: 40-60章/天
```

### 并行策略

**不要等全部完成再派下一批**

长暮的教训：等10章全到齐再读下一批大纲 = 浪费等待时间。

更好的方式：**前一批还有3-4章在跑时，就开始准备下一批的大纲和prompt**。

### 多分身调度协议

```
┌─────────────┐     ┌─────────────┐
│  大纲分身    │     │  正文分身    │
│  Ch881-900  │────→│  Ch126-130  │
│  先完成     │     │  等大纲完成  │
└─────────────┘     └─────────────┘
```

**规则：**
1. 两个分身都必须用引擎数据，禁止裸写
2. 正文分身必须等对应大纲完成后才能开始
3. 如果大纲和正文范围不重叠（写不同章节），可以并行
4. 每个分身完成后必须更新状态文件
5. **主体负责审查，不能让分身自检**
6. 分身的prompt必须由主体通过writer_dispatch.py生成后传递
