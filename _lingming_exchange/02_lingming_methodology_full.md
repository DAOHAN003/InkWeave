## 一、28条写作方法

### 基础写法
1. **情绪用身体写** - 不写"他很愤怒"，写"他的牙关咬得咯咯响"
2. **对话前后写动作** - 不写"他说"，写"他放下茶杯，说"
3. **用动作开场不用天气** - 不写"今天天气晴朗"，写"他推开门"

### 场景构建
4. **物品法则** - 每个场景至少3个具体物品
5. **八维度场景描写** - 视觉/听觉/嗅觉/触觉/味觉/温度/光线/空间感
6. **场景转换用小动作** - 不写"三天后"，写"他把最后一颗丹药收进怀里"
7. **环境反映心情** - 心情好时写阳光，心情差时写阴影
8. **空间感建立** - 先写大环境，再写小细节

### 情感与死亡
9. **死亡写法** - 用最后一个动作写死亡，不写"他死了"
10. **金句写法** - 金句不超过15字，放在段落结尾
11. **传承写法** - 传承用物件承载，不写"他继承了遗志"

### 冲突与转折
12. **冲突模板** - 冲突=目标+阻碍+行动，不写"他们打起来了"
13. **缺席证据** - 用缺席的东西写存在，如"空锅写谎言"
14. **微量变化** - 日常章用微小变化推进，不写"日子一天天过去"
15. **反高潮** - 高潮后接平静，不连续高潮

### 突破与战斗
16. **体质融入情感** - 突破时写身体感受，不写"他突破了"
17. **战斗写法** - 战斗写感官细节，不写"他一剑劈出"
18. **突破写法** - 突破写身体变化过程，不写"他变强了"

### 其他方法
19. **伏笔回收** - 伏笔回收时点明，不悄悄回收
20. **角色弧光** - 每卷结束角色有变化
21. **节奏控制** - 不连续3章同类型（日常/战斗/突破）
22. **字数控制** - 2500-3500字/章，不波动
23. **禁用词** - 禁用"竟然/然而/仿佛/宛如"等
24. **比喻上限** - 每章比喻不超过5个
25. **叠词上限** - 轻轻/缓缓等合计不超过2个
26. **破折号上限** - 每章不超过15个
27. **短行合并** - 非对话行≤15字合并
28. **段首不重复** - 连续段落开头不重复

## 二、15条铁律

### 原有铁律（v2）
1. **5章一个分身** - 不让一个分身写多章
2. **prompt不超20行** - 超过就砍
3. **不让分身读文件** - 信息贴在prompt里
4. **写完跑auto_pipeline.py** - 后处理必做
5. **质检不过才重写** - 大部分脚本能修
6. **角色信息从character_lock.json来** - 不手动记
7. **大纲从万象数据来不要人编** - 引擎生成
8. **每30章提取精华+进化标准** - 越写越好
9. **每批开写前更新story_state.json** - 状态追踪
10. **不赶进度不跳步骤** - 宁可慢不可烂

### v3新增铁律
11. **引擎跑不通不开写** - 引擎是前置条件，不是可选项
12. **分身不裸写** - prompt必须由writer_dispatch.py生成，禁止手写
13. **大纲也走引擎** - 大纲基于万象数据+伏笔+角色锁生成
14. **状态文件实时更新** - 每批完成后立刻更新story_state.json
15. **伏笔每批必检** - 开写前检查foreshadow.json，到期伏笔必须安排回收

## 三、18条血泪教训

### 原有教训（v2，10条）
1. **本地小模型写不了小说** - 用云端分身
2. **3段生成是给烂模型擦屁股** - 不如换好模型
3. **格式指标≠故事质量** - 质检侧重"有没有发生事件"
4. **引擎做太多=偷懒** - 引擎只做状态追踪，写作我来
5. **规则太多分身记不住** - 15行prompt是极限
6. **知识库太长分身读不完** - 方法由我消化不给分身
7. **分身自检不可信** - 用脚本检
8. **赶进度跳质检=全部返工** - 宁可慢不可烂
9. **一次10章分身偷懒** - 5章一批
10. **越搞越复杂反而跑不通** - 回到最简方案

### v3新增教训（8条，2026-05-08）
11. **引擎白做了等于没用** - 引擎是写作的前置条件，不是可选项。做了引擎却不用，等于白做。每次写作必须走引擎流程，这是纪律不是建议。
12. **分身裸写质量不可控** - 即使大纲足够详细，分身直接拿大纲裸写也会丢失伏笔追踪、角色锁定、精华匹配。引擎的28条方法论一条都用不上。正文质量可能"还行"，但完全脱离了引擎控制，状态追踪全断。
13. **数据源不通用引擎就跑不通** - 引擎硬编码了特定数据格式，换一本小说就跑不通。跑不通→自然不会用→引擎白做。新小说接入的第一步必须是适配数据源，确保引擎能读到数据。
14. **大纲手写脱离世界数据** - 大纲不走引擎，就不会检查伏笔回收时机，不会参考角色最新状态，和万象世界数据脱节。大纲也必须走引擎流程。
15. **多分身无协议等于各干各的** - 同时派大纲分身和正文分身，没有明确的依赖关系和状态同步机制，结果两个都裸写了。多分身必须有调度协议：谁先谁后、谁生成prompt、谁做审查。
16. **分身不读文件！信息贴在task里！** - 让分身自己去读文件=浪费时间=超时。我自己读好所有上下文，精简成短文直接贴在task里。分身拿到就写，不读任何文件。
17. **不给信息≠精简，分身是执笔者不是创作者** - 不让分身读文件，不等于只给几行状态。正确做法：我消化后给精华。分身需要：前文最后500字（衔接感）+ 质量锚点（写得最好的一段）+ 风格指南 + 每章骨架（我设计好的）。分身的工作是把骨架扩展成血肉，不是设计故事。创作在我这里完成。
18. **动作级大纲越详细，正文质量越高** - Ch126大纲最详细↗97分，Ch129大纲最粗↗68分。每章动作级大纲必须300-500字，含具体动作、对话、感官细节、小动作收尾。不能图省事。

## 四、动作级大纲模板

### 示例（Ch51 霜痕段落）

```markdown
## Ch51 动作级大纲

### 前情回顾
- 上一章结尾：沈夜在残灯镇外灭了三盏灯，灰焰渗入左手
- 当前状态：灭灯体暗蚀到左手肘，苏映寒霜痕扩散到右肩

### 本章大纲（300-500字）

**开场**（50字）
沈夜蹲在镇外破庙里，灰焰从指尖渗出，滴在青石板上发出嗤嗤声。
苏映寒靠在门框上，霜痕从右肩蔓延到锁骨，她咬着牙没出声。

**发展**（150字）
- 楚狂提着酒壶进来，壶里只剩半口酒
- 他看了看沈夜的左手，又看了看苏映寒的右肩，没说话
- 燕无归在角落磨剑，嚓嚓嚓的声音很规律
- 沈夜开口："暗海退了三步。"
- 楚狂把酒壶递过去："喝完再说。"

**高潮**（100字）
- 苏映寒突然咳嗽，霜痕从嘴里渗出来
- 沈夜站起来，灰焰在掌心凝聚
- "过这条线，砍。" 他指着庙门
- 燕无归的剑停在半空

**收尾**（50字）
三个人影子在残墙上拉得很长。
楚狂把空酒壶放下，说了两个字："走吧。"
```

### 动作级大纲要素
1. **前情回顾** - 上章结尾状态
2. **具体动作** - "他蹲下来，灰焰从指尖渗出"
3. **具体对话** - "过这条线，砍。"
4. **感官细节** - "酒穿过暮色像水穿过晨雾"
5. **收尾方式** - "用三个人的影子在残墙上拉得很长收束"

## 五、15行prompt模板

```
[角色] 3-5行：名字+性别+说话方式（从character_lock来）
[世界] 1行：书名+风格+基调+人称
[前文] 1-2行：上批最后一章的结尾摘要
[精华] 1-2行：本批最重要的2-3条精华构思
[大纲] 5行：本批5章大纲（1行/章）
[写法] 3行：字数+核心写法+禁忌
```

### 示例

```
[角色] 沈夜(他/极简)/苏映寒(她/冷)/楚狂(他/豪爽)/燕无归(他/沉默)
[世界] 《长暮》仙侠/克制/余韵悠长/第三人称
[前文] 沈夜灭了三盏灯，灰焰渗入左手，苏映寒霜痕扩散到右肩
[精华] 1.死亡用最后一个动作写(方法9) 2.空锅写谎言(方法13)
[大纲] 
Ch51: 破庙集结，楚狂半壶酒，沈夜说暗海退三步
Ch52: 苏映寒咳霜，沈夜画线，燕无归剑停
Ch53: 残灯镇入城，空锅旁老人说谎
Ch54: 灯老递包袱，"走吧"
Ch55: 镇外三影拉长，暮色如酒
[写法] 每章3000字。情绪用身体写。对话前后写动作。禁用：竟然/然而/仿佛/宛如
```

## 六、精华回收机制

### 触发时机
- 每30章自动触发一次
- 扫描最近30章

### 提取规则
- 章节质量 > 70 才提取
- 每章最多5条精华
- 类型：sentence/paragraph/dialogue/description/transition
- 标签：战斗/情感/转折/日常/悬疑/幽默/哲理/氛围/人物/世界观

### 匹配策略
- 章节类型→标签映射（battle→战斗/悬疑/紧张）
- 上下文关键词命中加分
- 质量分加权
- 返回top-3注入prompt

### 示例
```markdown
## 精华库（Ch1-30提取）

### Ch5 霜痕段落（质量95）
"霜痕从右肩蔓延到锁骨，她咬着牙没出声。"
标签：情感/人物
技巧：身体写情绪

### Ch12 灰焰段落（质量90）
"灰焰从指尖渗出，滴在青石板上发出嗤嗤声。"
标签：战斗/氛围
技巧：感官细节
```

## 七、进化策略机制

### 触发时机
- 停滞检测：最近10章fitness是否停滞（window=5, threshold=0.05）
- 每30章强制触发一次深度进化

### 策略进化
- 分析最近20章fitness历史，找出薄弱环节
- 用 Pareto 前沿筛选最优目标组合
- PDCA 引擎辅助决策（explore/exploit/revive）
- 情绪元认知引擎修正（mutation_modifier）

### 示例
```json
{
  "generation": 3,
  "emphasis": ["身体写情绪", "感官细节", "金句收尾"],
  "avoidPatterns": ["抽象情绪", "天气开场", "然而/竟然"],
  "targetMetrics": {
    "qualityScore": 85,
    "storyScore": 80,
    "formatScore": 90
  }
}
```

## 八、质检标准

### 故事性检查（主体执行）
1. **有事发生** - 章末和章初处境不同
2. **人物有行动** - 不是只观察，做了选择
3. **对话区分** - 遮住名字能分辨谁说的
4. **无复读** - 没有大段重复
5. **连续性** - 和上一章衔接

### 格式检查（脚本执行）
- 字数2500-3500
- 禁用词为零
- 比喻≤5个
- 叠词≤2个
- 破折号≤15个
- 短行合并

## 九、auto_pipeline后处理

```
python auto_pipeline.py [start] [end]
```

自动做7件事：
1. 削微微（保留1个）
2. 削破折号（保留15个）
3. 削比喻（保留5个）
4. 削叠词（轻轻/缓缓等合计≤2个）
5. 删禁用词（仿佛/宛如/犹如/竟然/然而等）
6. 合并短行（≤15字非对话行合并）
7. 截断过长章节（>3500字截到3200）

## 十、完整写作流程

```
┌──────────────────────────────────────────┐
│ 0. 新小说接入：适配数据源                   │
│    → novel_config.json配置data_source      │
│    → writer_dispatch.py --status 验证      │
├──────────────────────────────────────────┤
│ 1. 引擎检查：三问确认                      │
│    → 引擎跑通？数据源接上？状态最新？         │
├──────────────────────────────────────────┤
│ 2. 大纲生成（走引擎）                       │
│    → 万象数据 + 伏笔检查 + 角色锁           │
│    → 每批最多20章                          │
│    → 连续性审查                            │
├──────────────────────────────────────────┤
│ 3. prompt生成（引擎生成，禁止手写）           │
│    → writer_dispatch.py生成15行prompt       │
├──────────────────────────────────────────┤
│ 4. 分身写作（5章/批）                       │
│    → 分身只执行，不决策                      │
├──────────────────────────────────────────┤
│ 5. 后处理                                 │
│    → auto_pipeline.py修格式                │
│    → 更新story_state.json                  │
├──────────────────────────────────────────┤
│ 6. 质检（主体执行）                         │
│    → 故事性检查 > 格式检查                   │
│    → FAIL重写，PASS继续                     │
├──────────────────────────────────────────┤
│ 7. 精华回收（每30章）                       │
│    → 提取精华 + 进化标准                    │
└──────────────────────────────────────────┘
```
